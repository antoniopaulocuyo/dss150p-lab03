## Goal 2 — Data Profiling Findings

Profiling was performed on the raw source files (`customers.csv`, `products.json`, `orders.csv`) prior to writing staging transformation rules, per the lab's guidance that defect locations are intentionally undocumented and must be discovered through profiling.

### customers.csv
- **Row count:** 3,003
- **Duplicate `customer_id` values:** 3 (resolved via keep-latest-`updated_at` deduplication)
- **Missing `email`:** 4 rows (retained as a visible null quality condition, not quarantined, per spec)
- **Dirty `city` values:** at least one padded/mis-cased entry (`"  manila  "`) requiring trim + title-case normalization
- **No missing values** in `customer_id`, `first_name`, `last_name`, `city`, `customer_tier`, `created_at`, `updated_at`

### products.json
- **Row count:** 601
- **Duplicate `product_id` values:** 1 (resolved via keep-latest-`updated_at` deduplication)
- **Invalid price:** 1 record with `unit_price = -199` (quarantined — negative price)
- **Price range (valid):** min ~0 (excluding the invalid one), max ~89,926.78
- **Nested `category` object:** flattened into `category.name` → `category`, `category.department` → `department`
- **No missing values** in any column

### orders.csv
- **Row count:** 50,005
- **Duplicate `order_id` values:** 5 (resolved via keep-latest-`updated_at` deduplication)
- **Invalid quantity:** 1 record with `quantity = 0` (outside allowed range 1–20; quarantined)
- **Invalid status:** 1 record with `status = "UNKNOWN"` (not in allowed status list; quarantined)
- **Status distribution (valid values):** CANCELLED (8,461), DELIVERED (8,378), SHIPPED (8,372), PACKED (8,355), PAID (8,219), PENDING (8,219)
- **Orphan `customer_id` references:** 1 (does not match any staged customer)
- **Orphan `product_id` references:** 1 (does not match any staged product)
- **No missing values** in any column

### Rule Mapping Summary

| Dataset | Defect | Handling |
|---|---|---|
| customers | 3 duplicate business keys | Dedup, keep latest `updated_at` |
| customers | 4 missing emails | Retained as visible null (not quarantined) |
| customers | Dirty city formatting | Trim + title-case |
| products | 1 duplicate business key | Dedup, keep latest `updated_at` |
| products | 1 negative price | Quarantined (staging layer) |
| products | Nested category object | Flattened to `category`/`department` columns |
| orders | 5 duplicate business keys | Dedup, keep latest `updated_at` |
| orders | 1 out-of-range quantity | Quarantined (staging layer) |
| orders | 1 invalid status | Quarantined (staging layer) |
| orders | 1 orphan customer FK | Quarantined (curated layer, join step) |
| orders | 1 orphan product FK | Quarantined (curated layer, join step) |

**Note:** Orphan foreign-key references are intentionally *not* handled at the staging layer — the spec requires them to be caught during the curated cross-source join, since staging validates each dataset independently before any join occurs.
